# 訪談 → Playbook（SKILL.md）工具

把一項常重複的工作，透過一問一答的訪談，整理成 agent 可以照做的 SKILL.md。

## 使用方式
1. 把「啟動 Prompt」貼給 AI，替換 `[工作名稱]`。
2. 一次只回答一題，直到你說「訪談完成」。
3. 用「整理 Prompt」產出 SKILL.md，再用「驗證問題」修正。

---

## 啟動 Prompt

```
我要把一個我經常重複做的工作，整理成一套你之後可以自己執行的 Playbook。
這項工作是：[工作名稱]
先不要寫 SOP，也不要開始工作，請先訪問我。
一次只問一個問題，等我回答再問下一題，至少問 8～12 題。
等我明確說「訪談完成」後，再整理成 SKILL.md。
```

## 訪談題庫（依序問，一次一題）

| # | 要弄清楚的事 | 範例問法 |
|---|---|---|
| 1 | 工作範圍 | 這項工作具體包含哪些部分？多久做一次？ |
| 2 | 觸發時機 | 一個典型的日子裡，這件事在什麼時間點、因為什麼開始？ |
| 3 | 輸入資料 | 開始時你手上有哪些資料？哪些是已經決定好的？ |
| 4 | 先看什麼 | 拿到資料後，你怎麼判斷哪些最重要？ |
| 5 | 判斷優先順序 | 條件衝突時，請幫這幾項排順序。 |
| 6 | 實際步驟 | 照真實順序（不是理想狀況）一步一步怎麼做？用什麼工具？花多久？ |
| 7 | 好成品的定義 | 怎樣算「做得好」？用什麼數字或結果判斷？ |
| 8 | 討厭的 AI 成品 | AI 做成什麼樣子你會想直接刪掉？ |
| 9 | 語氣與句型 | 哪些寫法是你自己的？用什麼身分說話？ |
| 10 | 紅線 | 有哪些絕對不能做的事？ |
| 11 | 完成前檢查 | 交出去之前你會檢查什麼？ |
| 12 | 常犯的錯 | 過去最常出錯或最後悔的是什麼？ |
| 13+ | 子流程 | 每個子工作各問一次：誰提出需求、提前多久、內容怎麼定、怎麼交付、出過什麼狀況 |
| 最後 | 分工 | 你會給 agent 什麼？agent 要交回什麼？哪些一定要你看過？ |

**訪談原則**
- 對方的回答若和先前矛盾或有歧義，先複述你的理解，再問下一題。
- 對方答「都有」「沒有考量」時，記下來，標成「由 agent 設計，待確認」。
- 對方提到檔案、連結、截圖時，先打開看，再追問。

## 整理 Prompt

```
訪談完成。請整理成可長期使用的 SKILL.md，必須包含：
# Purpose / # When to use / # Inputs / # Steps / # Decisions / # Definition of Done / # Edge Cases
Decisions 盡量用「如果 X，就做 Y」「如果 X，不要做 Y，改成 Z」。
不要加入我沒說過的規則；不確定的地方另外列出來問我。
最後問我：1. 哪些地方你理解錯了？ 2. 還有哪些重要事情我忘記告訴你？
```

## SKILL.md 骨架

```markdown
---
name: [skill-名稱-英文小寫連字號]
description: [一句話用途]。Use for [觸發情境，中英並列以利觸發]。
---

# [工作名稱]

> 本文件只收錄 [當事人稱呼] 說過的內容；標「〔待確認〕」者為 agent 理解，尚未確認。

## Purpose
[一句話：為誰、做什麼、達成什麼結果]

## When to use
- [時間點或觸發事件]

## Inputs
- [輸入資料與格式]
| 固定資料 | 內容 |
|---|---|

## Steps
1. [實際順序的步驟]
**agent 交回：** [輸出清單]

## Decisions
- 如果 [條件]，就 [做法]。
- 如果 [條件]，不要 [做法]，改成 [替代做法]。

## Definition of Done
- [ ] [檢查項目]
成效依序看：[指標]

## Edge Cases
- [例外與常犯的錯]
```

## 驗證（整理完一定要做）
- 逐條比對：每條規則都能指出是對方哪一句話說的嗎？指不出來的就刪掉或標〔待確認〕。
- 把〔待確認〕集中列成問題清單一次問完。
